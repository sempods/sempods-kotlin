# Moving from 0.2 to 0.3

## Operator actions

**The pod server needs `SEMPODS_SECRET_KEY`.** It encrypts the PKCE verifier of every sign-in in
flight. Without it the server does not start. Set the same key on every replica:

```bash
SEMPODS_SECRET_KEY=$(openssl rand -base64 32)
```

Changing the key later fails only the sign-ins in flight. A local run takes the published key in
[`local.example.env`](../../deployments/local/env/local.example.env).

Sign-ins started before the upgrade, at the pod server and at the hosted MCP service, fail and have
to be started again. So does every sign-in that starts on a node of one version and returns to a
node of the other while both run side by side. The hosted MCP service needs no new setting: it
keeps using `MCP_SECRET_KEY`.

## Code changes

| 0.2 | 0.3 |
|---|---|
| `org.sempods.mcp.crypto.SecretCipher` | `org.sempods.auth.core.SecretCipher`, in `sempods-auth-core`. Same `v1:` envelope, so stored rows stay readable. `SecretCipher.fromEnv` is `McpSecretKey.cipherFromEnv` |
| `org.sempods.mcp.auth.LoginCsrfPin` | `org.sempods.commons.ktor.auth.BrowserPinCookie` for the cookie; `org.sempods.auth.core.BrowserSignIn` mints and compares the pin |
| A sign-in written around `OidcRelyingParty` | `BrowserSignIn`, which also checks `iss` (RFC 9207) |
| `OidcProviderMetadata(issuer, authorizationEndpoint, tokenEndpoint, jwksUri)` | two optional further arguments, `authorizationResponseIssParameterSupported` and `scopesSupported` |
| `copy(…)` on `OidcProviderMetadata` or `OidcRelyingParty.VerifiedIdentity`, compiled against 0.2 | recompile: both classes gained parameters, so the old `copy` fails with `NoSuchMethodError`. A Java caller of `copy` passes every parameter, the new ones included |
| `SempodsCredentials(…)` or its `copy(…)`, compiled against 0.2 | recompile: the class gained `identified`, `serviceClient` and `serviceRegistrationId`, so a Kotlin caller's 0.2 constructor with defaults and `copy` fail with `NoSuchMethodError`. A Java caller keeps the 0.2 constructor. Replace an anonymity check `credentials.oauthClientId == null` with `!credentials.authenticated`. An authorizer of a deployment's own sets `serviceClient` and `serviceRegistrationId` from `PodAccessToken`, or a service token holds no management authority |
| `org.sempods.pods.oauth.PodAccessToken` | `org.sempods.pods.oauth.spi.PodAccessToken`: change the import and recompile, since no class is left under the old name. It also gained `registrationId`, so its `copy` changed too; the six-argument constructor stays |
| `PendingLogin.pod`, `.codeVerifier`, `.nonce`, `.browserPin` | gone; `BrowserSignIn` keeps the round trip |
| A `find` sent through `SempodsSession` and `SempodsExchange` | `pod.find()`, which builds the body from a `SempodsFindQuery` and marks the request repeatable. `sempods-client-rdf4j` reads the answer as a model through `rdf4j().find()` |
