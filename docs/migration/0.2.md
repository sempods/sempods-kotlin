# Moving a client from 0.1.0 to 0.2

The pod client is three artifacts now, and the classes 0.1.0 consumers called are gone. This
lists what each entry point became, and the answers that changed shape. What the client *is* after
the move is [`../pod-client.md`](../pod-client.md).

## The coordinates

```kotlin
implementation(platform("org.sempods:sempods-bom:0.2.0"))
implementation("org.sempods:sempods-client")        // 0.1.0: the whole client
```

becomes one or more of

```kotlin
implementation("org.sempods:sempods-client-core")   // HTTP, the protocol's JSON, no RDF library
implementation("org.sempods:sempods-client-rdf4j")  // RDF4J values on the same session — needs Java 25
implementation("org.sempods:sempods-client-media")  // the media routes
```

`org.sempods:sempods-client` carries neither `PodWireClient` nor `SempodsHttpTransport` any more.

## Building a client

0.1.0 took a pod base URL and a token per call, or bound both in `SempodsPodClient`. 0.2 binds them
in a session, and one OkHttp client carries the policy:

```java
OkHttpClient http = SempodsOkHttp.install(new OkHttpClient.Builder()).build();

// Every 0.1.0 entry point took a `java.net.URI`; a pod base is validated from its text.
var base = SempodsPodBase.of(podBaseUrl.toString());

// A null token meant anonymous in 0.1.0; here it is which mechanism the session carries.
// `bearer` takes no null.
var auth = token == null ? SempodsRequestAuth.anonymous() : SempodsRequestAuth.bearer(token);
var session = new SempodsSession(base, auth);
var pod = new SempodsPod(session, http);
var rdf = new SempodsRdf4jPod(pod);      // for RDF4J values
var media = new SempodsPodMedia(pod);    // for the media routes

// The three reads that ask without a credential even when there is one — the note below says why.
var anonymous = new SempodsPod(new SempodsSession(base), http);

// A URI no pod serves: outside any session, and carrying a credential only when one is passed.
var foreign = new SempodsRdf4jForeignTarget(new SempodsForeignTarget(http));

// Minting a service token authenticates as the client, never with the pod bearer it is about to
// supply — a session of its own, so the mint cannot recurse into itself.
var clientSession = new SempodsSession(base, SempodsRequestAuth.clientSecretBasic(clientId, clientSecret));
```

**A null token is a different mechanism, not a null argument.** Every 0.1.0 method took `token:
String?`, and `null` read a pod's public data. `SempodsRequestAuth.bearer` takes no null: choose
`anonymous()` when there is no credential, as above. A consumer that holds one sometimes and not
others chooses per session rather than per call.

`SempodsAuth` becomes `SempodsRequestAuth`: `token()` is what `bearer` or `refreshable` supply, and
`invalidate()` is what `refreshable` does for you after a refusal. A credential that must be derived
per attempt implements the interface directly.

## What each call became

**Two things hold for the whole table.** An IRI travels as text: every removed method took a
`java.net.URI`, and the core addresses a resource, subject, slot or context by the IRI as a string,
so `uri.toString()`. And every write names its context in `SempodsWriteOptions.inContext(contextUri.toString())`,
which is where the old `contextUri` argument goes — `withIfMatch` on the same object is what makes the
write conditional, which 0.1.0 had no way to say.

| 0.1.0 | 0.2 |
|---|---|
| `getResource`, `putResource` | `rdf.resources().getModel(uri)`, `.put(uri, model, inContext(ctx))` — or `pod.resources()` for the bytes |
| `getSubject`, `putSubject`, `deleteSubject` | `rdf.subjects().getModel(iri, readIn(contexts))` / `.put(iri, model, inContext(ctx))`, `pod.subjects().delete(iri, inContext(ctx))` |
| `putSlot` | `rdf.slots().put(subject, predicate, values, inContext(ctx))` |
| `createContext(…, public, label, description)` | `pod.contexts().create(contextUri.toString(), SempodsContextCreate.fields().withPublic(public).withLabel(label).withDescription(description))` — the no-body form sets none of the three, and `getStatus() == 201` is the old `true` |
| `deleteContext`, `removeContext` | `pod.contexts().delete` — both threw on a refused removal; see the note below |
| `listContexts`, `contexts()` | `rdf.contexts().listIris()` |
| `publicContexts()` | `new SempodsRdf4jPod(anonymous).contexts().listIris()` |
| `dumpContext` | `pod.contexts().exportTo`, or `rdf.contexts().export` into an `RDFHandler` |
| `sparqlSelect` | `pod.sparql().resultsJson` |
| `sparqlSelectColumn` | `pod.sparql().select(...).getBody().column(name)`, then each term's `getValue()` |
| `sparqlAsk` | `pod.sparql().ask` |
| `sparqlConstruct` | `rdf.sparql().graphModel` |
| `lastModifiedAt()`, `fetchPodLastModifiedAt(url)` | `anonymous.metadata().dateModified().getBody()` — then `getDateModified()` for the `Instant` |
| `fetchPodLastModifiedAt(url, token)` | the same on `pod` — a bearer here authenticates the read, which is what records the audit row |
| `podExists`, `exists()` | `anonymous.metadata().exists()` |
| `dereference(uri)` | `foreign.getModel(uri.toString(), List.of(RDFFormat.NQUADS, RDFFormat.JSONLD))` — check `getStatus()`; see the note below |
| `dereference(uri, token)` | the same, plus the `auth` built above — `bearer(token)`, or `anonymous()` where 0.1.0 passed null. See the note below |
| `mintServiceToken` | `new SempodsPodTokens(clientSession, http).clientCredentials()` — the client's own credential, not the pod bearer |
| `uploadMedia`, `uploadMediaFromUrl`, `assignMedia`, `unassignMedia` | `media.upload(ctx, contentType, source, length, filename)`, `.uploadFromUrl`, `.assign`, `.unassign` — `length` is a `long`, so an unknown size is `-1` where 0.1.0 passed `null` |
| `deleteResource`, `delete(...)` | `pod.resources().delete(uri, inContext(ctx))` under the pod, `pod.subjects().delete(iri, inContext(ctx))` for a subject it does not host |
| `ServiceTokenResponse` | `SempodsTokenResponse` |

**A column the result does not declare is an error, not an empty list.** `sparqlSelectColumn`
skipped what it could not find, so a query whose projection varies quietly returned nothing;
`SempodsSparqlResults.column` requires a declared variable and throws `IllegalArgumentException`
otherwise. Check `getVariables()` first where the projection is built at runtime.

**A foreign read reports every status as an answer.** `dereference` threw for anything outside 2xx
except a 404, which it reported as `null`. `SempodsForeignTarget` — and the RDF4J adapter over it —
treats every status as an answer with its headers and, outside 2xx, no body, because a URI nobody
serves on your behalf answers what it answers. So a 403 and a 500 arrive as a null body, exactly like
the 404 that used to mean "not there": check `getStatus()` before reading, or an authorization failure
migrates into an absent resource.

**A foreign read carries no credential unless you hand it one.** `dereference` took a token;
`SempodsRdf4jForeignTarget` — built over `new SempodsForeignTarget(http)` — defaults to
`SempodsRequestAuth.anonymous()`, and the pod session's bearer deliberately does not reach it, because
the target is outside the pod that issued it. A protected resource answers an anonymous read with
something else rather than with an error, so pass the credential explicitly where 0.1.0 passed a
token. The formats are yours to name too: the read asks for them in order and the answer's
`Content-Type` picks the parser.

**A removal that did not happen is an answer, not an exception.** Both `deleteContext` and
`removeContext` threw on the `409` a pod gives for the last context its caller can see;
`pod.contexts().delete` lists that status, so it returns a `SempodsResponse` carrying it. A migrated
call that ignores the result continues as though the context were gone — check `getStatus()`, or wrap
the call the way the facades did.

**`getBody()` is not always the old type.** Beyond the response wrapper itself, four answers changed
shape inside it:

- `dateModified()` answers a `SempodsPodDateModified`; the `Instant?` is its `getDateModified()`, and the
  body itself is null for the `404` of a pod the server does not know.
- `column(name)` answers `SempodsSparqlTerm`s; the `List<String>` the old method gave is their
  `getValue()`.
- `listIris()` answers RDF4J `IRI`s where `listContexts` answered `java.net.URI`.
- `clientCredentials()` answers a `SempodsTokenResponse`, whose `getExpiresIn()` is a `Duration`
  where `ServiceTokenResponse.expiresInSeconds` was a `Long`.

And one answer is not in the body at all: `createContext` returned `true` for a context this call
created and `false` for one that was already there, which is `getStatus() == 201` now — the body is
the context's description (SPS-CTX-016).

**Three reads ask without a credential, and the session is where that is decided.** `exists()`,
`lastModifiedAt()` and `publicContexts()` never consulted `SempodsAuth`: the metadata route accepts
an anonymous caller but answers `401` for a bearer it cannot verify, so an expired token would turn a
public existence check into a failure — and the catalogue answers a credential with that client's own
grants rather than the public contexts. Run them on a session without one.

**Three conveniences have no successor**, and that is deliberate: `existsResource`,
`findReferencingResources` and `sparqlSelectStatements` build or project SPARQL, and the client
executes queries rather than writing them
([`concepts/modularity.md`](../concepts/modularity.md) §"The service contract is semantic, not a
facade over RDF"). Each is a few lines over `pod.sparql()` in the code that knows the question.

## The wire layer

The core answers the same unparsed bytes, so the move is which object you call. What was
`PodResource.etag`, `PodSlot.etag` and `PodWriteResult.etag` is the answer's `ETag` header, and what
was `jsonld`, `values` or `body` is `getBody()`.

`SempodsHttpTransport` splits into the three pieces it combined: `SempodsOkHttp.install` configures
the engine, a `SempodsSession` binds the pod and the credential once instead of a token per call,
and `SempodsExchange` runs a request the session built. `SempodsHttpTimeouts` has no successor:
its four values go on the `OkHttpClient.Builder` itself. `call` is OkHttp's `callTimeout`, which
`install` sets to two minutes where the builder carries none and a caller tightens or lifts per
call; `connect`, `read` and `write` are `connectTimeout`, `readTimeout` and `writeTimeout`, which
`install` does not touch — a figure you passed to `SempodsHttpTimeouts` has to be set there, or it
falls back to OkHttp's own default of ten seconds each.

| 0.1.0 `PodWireClient` | 0.2 |
|---|---|
| `listContexts` | `pod.contexts().listText()` |
| `sparqlSelect`, `sparqlGraph` | `pod.sparql().resultsJson(query, selection)`, `.graphText(query, JSON_LD, selection)` — the context list is a `SempodsContextSelection` |
| `find` | no group speaks it — a request of your own through `SempodsExchange`, below the table |
| `getResource` | `pod.subjects().getText(iri, JSON_LD, readIn(contexts).withIncludeContexts(includeContexts))` — the flag is off by default, so carry it |
| `createResource` | `pod.subjects().put(iri, JSON_LD, SempodsContent.of(jsonld), inContext(ctx).withIfNoneMatch(tag))` |
| `updateResource` | `pod.subjects().patch(iri, SempodsContent.of(patch), inContext(ctx).withIfMatch(tag))` |
| `deleteResource` | `pod.subjects().delete(iri, inContext(ctx).withIfMatch(tag))` |
| `getPropertyValues` | `pod.slots().getJson(subject, predicate, readIn(contexts))` |
| `addPropertyValue` | `pod.slots().add(subject, predicate, SempodsContent.of(value), inContext(ctx).withIfMatch(tag))` |
| `setPropertyValues` | `pod.slots().put(subject, predicate, SempodsContent.of(values), inContext(ctx).withIfMatch(tag))` |
| `removePropertyValue` | `pod.slots().removeEdge(subject, predicate, target, inContext(ctx))` — it accepts no condition |
| `clearPropertyValues` | `pod.slots().clear(subject, predicate, inContext(ctx).withIfMatch(tag))` |

**`find` is the one operation with no endpoint group**, so it stays a request you build yourself —
which is what `SempodsExchange` is for. The route is a literal here, because `sempods-client-core`
resolves no `sempods-commons` to read `SempodsPodRoutes` from, and the body is the JSON
`PodWireClient` sent, in which `text` is the one required member:

```java
// {"text": …} plus the optional "type", "contexts", "include_contexts" and "limit"
byte[] body = searchDocument();

Request request = SempodsRepeatable.mark(pod.getSession().newRequest("POST", "_system/find"))
    .header("Accept", "application/ld+json")
    .post(RequestBody.create(body, MediaType.get("application/json")))
    .build();

SempodsResponse<String> found = new SempodsExchange(pod.getCalls()).text(request, 200);
```

`SempodsRepeatable.mark` is what keeps the search resendable after a lost connection: the route
spells a read as `POST`, and the core repeats no `POST` without that mark.

**Six `SempodsPodRoutes` constants went with it**, in `org.sempods:sempods-commons`:
`SPARQL_QUERY`, `META_DATE_MODIFIED`, `AUTH_TOKEN`, `context(path)`, `slot(subject, predicate)` and
`slotValue(subject, predicate, target)`. Each is a path the endpoint group that dials it now owns —
`pod.sparql()`, `pod.metadata()`, `SempodsPodTokens`, `pod.contexts()` and `pod.slots()`. What stays
is what the pod server and the clients both spell: the two prefixes, `CONTEXTS`, `FIND`, `MEDIA`,
`AUTH_OIDC_CALLBACK` and `resource(iri)`.

**`SempodsCallSlot` is gone too.** It was the handle a caller installed around blocking work on that
transport with `using`, to cancel it from another thread. Work that has to be abortable runs on the
core instead, where the operation owns its calls rather than the thread:

```java
SempodsAsyncOperation<SempodsResponse<String>> read =
    new SempodsAsync(http).submit(calls -> new SempodsPod(session, calls).contexts().listText());
read.cancel();
```

`cancel()` reaches every call the work made through the `Call.Factory` it was handed, a call nested
inside another call's body or read included — which a handle per thread could not do.

## Answers that changed shape

- **An operation answers a `SempodsResponse`**, carrying the status and the headers rather than only
  a value. `getBody()` is the value; it is null exactly for a listed status outside 2xx, such as a
  404 for a resource that is not there.
- **A malformed answer fails.** 0.1.0 read leniently: a broken SPARQL result could come back as
  `false` or as no rows, and an `ASK` whose `boolean` was not one was coerced. Each of these is a
  `SempodsDecodingException` now, carrying the answer's status.
- **The context catalogue is read as RDF.** The JSON envelopes the registry answered on
  `application/json` are not asked for any more.
- **A buffered answer is bounded at 16 MiB**, `sparqlSelect` included. A query whose result runs
  larger is one to page.
- **Failures are `IOException`s.** The core's `SempodsClientException` and its
  `SempodsStatusException` / `SempodsDecodingException` replace the unchecked exception of 0.1.0;
  status and the server's excerpt are on the exception.
- **Deleting a subject the pod does not host is one call.** 0.1.0 read the subject's predicates and
  cleared each slot in turn; `subjects().delete` does it in one.
- **A narrowed read says so, and an empty list is not "every context".** `getSubject` took the
  contexts to read from; a read without `SempodsReadOptions` reads everything the session may see, so
  a non-empty list becomes
  `SempodsReadOptions.of(SempodsContextSelection.of(contexts.stream().map(URI::toString).toList()))` — `readIn(contexts)`
  in the table. An empty one meant everything readable, where `SempodsContextSelection.of(emptyList())`
  selects nothing: `SempodsContextSelection.readable()` is the old meaning.
- **A media id carrying path separators is refused** before anything is sent, rather than encoded and
  sent.

## The host-level admin client

`SempodsControlPlaneClient` runs on the same core now, so it is built the way a pod client is and
answers the way one does.

```java
OkHttpClient http = SempodsOkHttp.install(new OkHttpClient.Builder()).build();

// 0.1.0: new SempodsControlPlaneClient(URI.create(serverBaseUrl), adminSecret)
var admin = new SempodsControlPlaneClient(
    new SempodsSession(SempodsPodBase.of(serverBaseUrl), SempodsRequestAuth.bearer(adminSecret)),
    http);
```

**The secret is a mechanism now.** `SempodsRequestAuth.bearer` is what 0.1.0 stamped by hand;
`apiKeyHeader`, `clientSecretBasic`, `refreshable` and a mechanism of your own work here exactly as
they do on a pod session.

**The server base is validated.** `SempodsPodBase.of` accepts a server root as it stands: its clauses
ask for no pod segment. What it refuses is `http` on anything but a loopback address, so a deployment
reaching its server over plain HTTP on a routable address has to terminate TLS in front of it.

| 0.1.0 | 0.2 |
|---|---|
| `createPod(pod, owner)` → `CreatePodResult` | `SempodsResponse<CreatePodResult>` — `getBody()` is the old value |
| `deletePod(pod)` → `void` | `SempodsResponse<byte[]>` |
| `podExists(pod)` → `boolean` | `SempodsResponse<byte[]>` — `getStatus() != 404` is the old value, and a 404 answers with a null body |
| `provisionServiceClient(…)` → `ProvisionServiceClientResult` | `SempodsResponse<ProvisionServiceClientResult>` |

**Failures are the core's**, as they are for the pod client: `SempodsStatusException` with `status`
and `bodyExcerpt` in place of the unchecked exception with `statusCode` and `responseBody`, and an
answer that is not the route's document is a `SempodsDecodingException`. Both are `IOException`s, so
every method declares one.

**The status a route does not answer is a failure.** 0.1.0 accepted any 2xx; each operation now
lists what its route answers — 201 and 200 for a creation, 204 for a removal, 200 and 404 for the
existence check, 200 for a provisioning — and anything else carries its status to the caller.
